# 亲子矛盾 RAG 智能问答平台 - 设计方案

> **EverGrow** - 陪伴家庭成长的智能育儿顾问

---

## 一、项目概述

### 1.1 愿景

打造一个面向家庭的智能问答平台，针对 **0-18 岁** 各成长阶段中父母与子女可能出现的典型矛盾，基于专业知识库提供**可检索、可溯源、可操作**的解决方案，帮助家庭建立更好的亲子关系。

### 1.2 核心价值

| 维度 | 说明 |
|------|------|
| **分阶段** | 按幼儿期、学龄前、小学、初中、高中等不同发展阶段精准匹配 |
| **可溯源** | 答案基于权威育儿/心理学文献，提供引用来源 |
| **可操作** | 解决方案具体、分步骤，而非泛泛而谈 |
| **个性化** | 结合用户描述的情境，进行上下文感知的推荐 |

## 二、内容分层架构

### 2.1 年龄段划分

```
幼儿期 (0-3岁)   → 学龄前 (3-6岁)  → 小学低年级 (6-9岁)  → 小学高年级 (9-12岁)
                                              ↓
初中 (12-15岁)   → 高中 (15-18岁)
```

### 2.2 矛盾类型分类（示例）

| 类别 | 幼儿期 | 学龄前 | 小学 | 初中 | 高中 |
|------|--------|--------|------|------|------|
| **行为习惯** | 吃饭难、睡眠、如厕 | 拖拉、挑食、规则感 | 作业拖延、粗心 | 手机依赖、作息紊乱 | 沉迷游戏、熬夜 |
| **情绪管理** | 哭闹、分离焦虑 | 发脾气、攻击性 | 畏难、挫败感 | 易怒、叛逆 | 焦虑、抑郁倾向 |
| **社交发展** | 认生、争抢 | 不合群、打人 | 霸凌、友谊 | 同伴压力、早恋 | 社交回避、恋爱观 |
| **学习态度** | - | 不爱阅读、专注力 | 厌学、成绩波动 | 偏科、考试焦虑 | 志愿选择、升学压力 |
| **亲子沟通** | 说不听、听不懂 | 顶嘴、说谎 | 隐瞒、顶撞 | 闭门、冷战 | 价值观冲突、代沟 |
| **生活自理** | 穿衣、洗漱 | 独立睡觉、整理 | 零花钱、家务 | 隐私、打扮 | 经济观、职业观 |

*可根据实际知识库内容进行细化和补充*

### 2.3 知识单元结构

每条知识条目建议包含：

```yaml
id: unique_id
title: 矛盾/问题描述（简短）
stage: [幼儿期|学龄前|小学低年级|小学高年级|初中|高中]
category: [行为习惯|情绪管理|社交发展|学习态度|亲子沟通|生活自理|其他]
keywords: [标签1, 标签2, ...]
description: 问题现象描述（供检索）
causes: 可能的成因分析
solutions: 分步骤的解决方案
prevention: 预防建议
source: 引用来源
related: [相关条目id]
```

## 三、语料库分析（基于 data 目录）

### 3.0 语料概览

基于 `data/` 目录下现有语料的统计与分析：

| 指标 | 数值 |
|------|------|
| **总文件数** | 208 |
| **格式** | .docx 154 个，.doc 54 个 |
| **来源特征** | 文件名含作者/机构（如韩晓芝、陈灵芝、李冠军、潍坊市实验学校等），多为专家或学校分享内容 |

### 3.1 内容结构（实测）

每篇文档通常呈现统一的「问题→原因→解法」结构，例如：

```
[标题/问题] 如「如何激发孩子的学习热情？」
    ↓
[背景描述] 问题现象、影响
    ↓
[原因1] 产生畏难情绪，逃避学习
  [解决方法] (1)(2)(3) 分点、可操作
[原因2] 学习没有成就感
  [解决方法] (1)(2)(3)(4)
[原因3] 缺乏目标感
  ...
```

- **问题导向**：每篇围绕一个具体育儿/亲子问题
- **分点清晰**：原因与解法均有编号，便于结构化提取
- **可操作性强**：解法多为具体步骤，适合直接推荐给家长

### 3.2 主题与年龄段覆盖（从文件名推断）

| 年龄段/阶段 | 示例主题 |
|-------------|----------|
| **幼儿期** | 如何培养幼儿劳动能力、幼儿刷牙习惯、幼儿入园适应 |
| **学龄前/幼小衔接** | 孩子上幼儿园不受欢迎、是否需要提前学小学知识 |
| **一年级** | 过分依恋父母、坐姿不正确、不喜欢老师、同伴关系 |
| **小学** | 学习热情、拖拉磨蹭、写字潦草、集体荣誉感、情绪调节 |
| **初中/青春期** | 心理营养、价值观、考试焦虑、沉迷游戏、亲子沟通 |
| **家庭通用** | 金钱观、自理能力、家长与学校配合、事业与家庭平衡 |

### 3.3 数据接入建议

| 环节 | 建议 |
|------|------|
| **格式解析** | `.docx` 用 `python-docx`；`.doc` 需 `pywin32`（Windows）或 `antiword`/`textract`（跨平台） |
| **切分策略** | 首选**按文档整体**作为检索单元（单篇即一个完整问题解答）；备选：按「原因+对应解法」块切分，提高细粒度召回 |
| **元数据抽取** | 从文件名解析：问题标题、年龄段关键词（一年级/小学/青春期等）、作者（如有） |
| **结构化抽取** | 可用正则或简单规则从段落中提取「原因」「解决方法」等字段，丰富检索与展示 |

### 3.4 与设计蓝图的关系

- 语料内容与蓝图中的**矛盾类型**高度吻合（学习、习惯、情绪、社交、亲子沟通等）
- 可直接将 `data/` 作为**原始知识源**，经解析、切分、向量化后接入 RAG 检索
- 建议在 ingest 阶段为每条记录打上 `stage`、`category` 等标签，便于后续按年龄段/类型过滤

## 四、RAG 系统架构

### 4.1 整体流程

```
┌─────────────┐     ┌──────────────┐     ┌─────────────────┐
│  用户提问   │ ──→ │ 意图理解     │ ──→ │ 查询改写/扩展   │
└─────────────┘     │ (可选 NLU)   │     │ (Query Expand)  │
                    └──────────────┘     └────────┬────────┘
                                                  │
                    ┌─────────────────────────────┘
                    ▼
┌───────────────────────────────────────────────────────────┐
│                    向量检索 (Retrieval)                     │
│  ┌─────────────┐  ┌─────────────┐  ┌─────────────────────┐ │
│  │  embedding  │  │ 相似度搜索   │  │ 年龄段/类别过滤     │ │
│  │  模型编码   │  │ (向量库)     │  │ (可选混合检索)      │ │
│  └─────────────┘  └─────────────┘  └─────────────────────┘ │
└───────────────────────────────────────────────────────────┘
                    │
                    ▼
┌───────────────────────────────────────────────────────────┐
│                    重排序 (Rerank)                         │
│  按相关度、年龄段匹配度、可信度等对候选文档排序              │
└───────────────────────────────────────────────────────────┘
                    │
                    ▼
┌───────────────────────────────────────────────────────────┐
│                    生成 (Generation)                       │
│  将检索到的文档作为 context，由 LLM 生成结构化、可溯源回答   │
└───────────────────────────────────────────────────────────┘
                    │
                    ▼
┌───────────────────────────────────────────────────────────┐
│  输出：回答 + 引用来源 + 相关推荐                           │
└───────────────────────────────────────────────────────────┘
```

### 4.2 检索策略

| 策略 | 说明 |
|------|------|
| **纯向量检索** | 基于语义相似度，适合自然语言提问 |
| **混合检索** | 向量 + 关键词（BM25），提高召回精确度 |
| **元数据过滤** | 用户选择「年龄段」时，先过滤再检索 |
| **多路召回** | 标题、描述、解决方案分别检索后融合 |

### 4.3 知识库构建流程

```
原始文档 (data/*.docx, *.doc)
        │
        ▼
┌───────────────┐
│  文档切分     │  按段落/语义块切分，保留元数据
└───────┬───────┘
        │
        ▼
┌───────────────┐
│  向量化       │  使用 embedding 模型生成向量
└───────┬───────┘
        │
        ▼
┌───────────────┐
│  存储         │  向量库 (Milvus/Chroma/Pinecone/Qdrant)
└───────────────┘
```

## 五、技术栈与配置管理

### 5.1 核心组件

| 模块 | 选用技术 | 说明 |
|------|----------|------|
| **LLM** | 云物 (yunwu.ai) OpenAI 兼容 API | `gpt-5.2-chat`，LangChain 自动读取 `OPENAI_API_KEY`、`OPENAI_BASE_URL` |
| **Embedding** | text-embedding-ada-002 | 可选 text-embedding-3-small / 3-large |
| **向量库** | Chroma | 由 `config/chroma.yml` 配置 |
| **业务数据库** | MySQL + PyMySQL | 由 `config/database.yml` 配置 |
| **RAG 框架** | LangChain | - |
| **后端** | FastAPI | - |
| **前端** | Streamlit / React | MVP 阶段可用 Streamlit |

### 5.2 配置管理

采用 **`.env` + `.yml`** 分工：敏感凭据放 `.env`，非敏感基础设施配置放 YAML。

| 配置文件 | 用途 | 是否纳入版本控制 |
|----------|------|------------------|
| **.env** | API Key、JWT 密钥、数据库密码等敏感信息 | ❌ 否 |
| **config/*.yml** | 数据库连接、向量库参数、切分配置、提示词等 | ✅ 是 |

#### .env（敏感凭据）

```env
OPENAI_API_KEY=xxx
OPENAI_BASE_URL=https://yunwu.ai/v1
OPENAI_MODEL_NAME=gpt-5.2-chat
EMBEDDING_MODEL_NAME=text-embedding-ada-002
TAVILY_API_KEY=xxx          # 智能搜索（可选）
JWT_SECRET_KEY=xxx          # 用户鉴权
DATABASE_PASSWORD=xxx       # 数据库密码（建议从 .env 读取，生产环境）
```

#### config/database.yml（业务数据库）

使用 **PyMySQL** 连接 MySQL，配置示例：

```yaml
database:
  host: localhost
  port: 3306
  database: evergrow_db
  user: root
  password: ${DATABASE_PASSWORD}   # 建议从 .env 引用
```

#### config/chroma.yml（向量库与文档处理）

```yaml
collection_name: agent
persist_directory: data/chroma_db
k: 3
data_path: data/raw
md5_hex_store: md5.txt
allow_knowledge_file_type: ["txt", "pdf", "docx"]   # 含 .doc 时需添加 "doc"
chunk_size: 200
chunk_overlap: 20
separators: ["\n\n", "\n", ".", "!", "。", "?", " ", ""]
```

- `data_path`：原始文档目录。若语料在 `data/` 根目录，需改为 `data/` 或迁移至 `data/raw`
- `allow_knowledge_file_type`：语料含 54 个 `.doc` 时，需增加 `"doc"`
- 设计建议「按文档整体检索」，若采用 `chunk_size: 200` 细粒度切分，可结合整篇摘要做混合召回

#### config/prompts.yml（提示词模板）

用于 RAG 系统提示、问答模板等。写作指南见 [prompts写作指南.md](prompts写作指南.md)。

- 密码等敏感项统一从 `.env` 读取，YAML 中可用 `${VAR}` 引用
- 使用 `python-dotenv` 加载 `.env`，`PyYAML` 或 `pydantic-settings` 加载 YAML

### 5.3 数据库设计

详细设计见 [数据库设计.md](数据库设计.md)，共 **4 张表**：

| 表 | 用途 |
|------|------|
| knowledge_articles | 知识元数据 |
| users | 用户（初始 admin/admin） |
| conversations | 问答会话（支持匿名） |
| conversation_messages | 消息与引用 |

- 建表脚本：`python scripts/init_db.py`（推荐）或 `sql/init_schema.sql`
- 连接方式：PyMySQL + config/database.yml

## 六、核心功能模块

### 6.1 用户侧功能

1. **智能问答**
   - 自然语言描述问题（支持模糊、多轮）
   - 可选：选择年龄段、矛盾类型进行筛选
   - 输出：结构化回答 + 引用来源 + 相关话题推荐

2. **话题浏览**
   - 按年龄段 / 矛盾类型浏览知识库
   - 支持收藏、笔记

3. **场景卡片**
   - 预设「孩子写作业拖拉」「孩子沉迷手机」等场景
   - 一键进入对应问答流程

### 6.2 管理侧功能（可选）

- 知识库增删改
- 问答效果反馈（点赞/点踩）
- 检索与生成日志分析

## 七、数据与安全

### 7.1 数据来源

- **主要语料**：`data/` 目录下 208 篇 docx/doc（专家/学校分享，涵盖幼儿至青春期各阶段）
- 育儿书籍、心理学教材（需版权合规）
- 权威机构公开资料（卫健委、教育部等）

### 7.2 隐私与合规

- 用户提问可脱敏后用于模型优化（需征得同意）
- 不存储可识别个人的家庭信息
- 输出需注明「仅供参考，严重问题请咨询专业机构」

## 九、总结

本设计方案围绕「**分阶段 + 可溯源 + 可操作**」三个原则，通过 RAG 将专业知识与 LLM 生成能力结合，为亲子矛盾提供高质量、可信的智能解答。建议从 MVP 起步，以真实用户反馈驱动知识库与模型迭代，逐步形成可运营的产品形态。
